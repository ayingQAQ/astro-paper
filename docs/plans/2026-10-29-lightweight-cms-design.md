# Wenying 轻量后台设计

## 目标

在常见 Linux VPS 上管理现有 Astro 博客：登录后新建、修改文章、上传图片、保存草稿和发布。前台页面设计保持不变，文章继续使用现有 Markdown 格式。实现不依赖 Ubuntu 特有工具或目录布局。

## 页面与视觉

- `/admin/`：登录后显示文章列表，提供标题搜索、全部/草稿/已发布筛选和“写文章”按钮。每项仅展示标题、状态、更新时间和编辑入口。
- 编辑页：标题和正文占主要空间；提供精简 Markdown 工具栏（标题、加粗、链接、图片）及预览切换。摘要、标签、地址、发布时间、首页精选放在“文章设置”折叠区域。
- 保存草稿与发布为明确的两个动作；已发布文章的未发布修改显示为“有修改”。离开未保存内容时提醒。
- 沿用 Georgia 的 Wenying 标题、现有字体和主题颜色；细边框、留白、少量按钮，适配手机和键盘。参考 UI Handbook 的表单、反馈和触控规范。
- 不增加统计仪表盘、多用户角色或独立媒体库。图片从编辑器上传并插入正文。

## 内容与草稿

- 现有 `src/content/posts` 作为发布内容，兼容原有目录与字段。
- 私有工作目录保存新文章草稿、已发布文章的修改副本和上传暂存文件，不进入静态输出或 Git。
- 保存草稿不修改线上文章；上传文件限制类型与体积，生成安全文件名，发布时复制到公开图片目录。
- 不把未保存的编辑内容发送给第三方。预览禁用原始 HTML 与脚本执行；现有 MDX 可使用源码方式编辑，预览不执行其组件。
- 发布前验证文章字段，防止覆盖其他文章或写出允许目录；已有文章默认保持地址不变。

## 服务与安全

- 独立 Node.js 服务提供后台页面和 API，与静态 Astro 前台并行运行，无需数据库。
- 单管理员密码由部署时配置，服务器保存密码散列；登录使用 HttpOnly 会话 Cookie，线上启用 Secure 与 SameSite。
- 写操作要求有效会话及同源/CSRF 校验；登录限速。凭据不放入前端或仓库。
- 上传拒绝 SVG、可执行文件和路径穿越，校验真实图片格式，设置文件和请求大小上限。
- 原生服务默认仅监听本机，通过反向代理提供 HTTPS；代理可使用 Nginx、Caddy 等。systemd 仅作为可选进程管理示例，不作为运行依赖。

## Linux 部署兼容性

- 推荐 Docker Compose：提供固定运行时版本的镜像与持久化卷，将文章、图片、草稿、会话与发布记录存放到可备份目录，避免重建容器丢失内容。
- 同时支持原生 Node.js：明确 Node.js、pnpm 版本与启动命令，通过环境变量配置监听地址、端口和数据路径，不在应用中执行 apt、yum 或 dnf。
- 面向 Debian/Ubuntu、Fedora/RHEL 系、Arch 等常见发行版；不要求统一包管理器或 init 系统。
- 构建涉及 Sharp 原生依赖，容器优先使用 Debian/glibc 基础镜像。原生安装的 CPU 架构、libc 与运行时兼容性在文档中说明；未实测的发行版不宣称已验证。
- Windows 保留本地开发支持，Linux 发布过程的文件切换与权限策略单独验证。

## 发布流程

1. 保存当前内容为私有工作副本，创建发布任务；前端显示处理中并防止重复提交。
2. 在独立临时工作区中合入待发布文章与图片，构建 Astro 和 Pagefind；不会直接修改当前线上文件。
3. 成功后保存正式内容，通过同文件系统内的原子切换更新静态发布目录。记录结果并保留上一版本用于回退。
4. 构建失败时保留原站点和工作副本，显示可理解的错误及重试操作。发布任务串行执行，避免并发覆盖。

后台发布直接更新 VPS；GitHub 代码推送与内容备份是独立操作，不在初版中自动提交 Git。

## 交付与验证

- 提供本地运行命令、管理员初始化方式、环境变量示例、通用 Linux 与 Docker Compose 部署说明，以及可选 Nginx、systemd 示例。
- 验证登录/退出、未授权写入、路径限制、上传校验、草稿隔离、文章编辑往返及发布成功/失败流程。
- 验证手机与桌面编辑界面，原前台样式和明暗切换保持一致。
- 完成本地实现和验证后，可使用用户提供的 VPS 连接方式部署；未取得服务器访问权限时不声称已经上线。
