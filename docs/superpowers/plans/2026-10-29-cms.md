# Wenying CMS Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Provide a small authenticated writing and publishing interface without changing the public blog.
**Architecture:** Standalone Node HTTP service, private filesystem drafts, immutable published releases with an atomically replaced pointer. Reuse YAML, markdown-it, sanitize-html and Sharp; no database or frontend framework.
**Tech Stack:** Node 24, existing Astro pipeline, vanilla browser JavaScript and CSS.
**Spec:** docs/plans/2026-10-29-lightweight-cms-design.md

## Global Constraints

- Common Linux support through native Node or Docker; local Windows development.
- Keep public blog design, Markdown content, single administrator and small writing UI.
- Drafts and staged images stay private. Never replace a successful site with failed output.
- Credentials remain server-side; authenticated writes require same-origin and CSRF checks.

## Review Focus

- Existing Markdown/MDX metadata survives editing; MDX preview never executes code.
- Stale browser tabs cannot overwrite newer drafts or published changes.
- Image MIME spoofing, traversal, symlinks and unbounded uploads are rejected.
- Build errors or service restart leave current release intact.
- Private unpublished files and administrative endpoints never enter the static site.

## Implementation clarification

The CMS serves public files through a release pointer as well as `/admin/`; the reverse proxy forwards both to the service. This avoids platform-specific symlink switching. Once initialized, published content is authoritative in the private data directory rather than the source checkout. Each release retains source content for recovery/export; GitHub synchronization remains manual.
